# Run 007 — Systems Intelligence & Development Team

## Purpose
Continuously identify missing capabilities, recurring friction, emerging risks, duplicated work, and high-value opportunities across the operating system before they become owner-visible problems.

Run 007 also owns the mandatory **A0 Architecture Discovery Gate** for substantial new Agent Team Factory work. Its job is to understand the complete system before the Factory optimizes one component inside it.

## Core loop
Observe → Detect → Evidence → Challenge → **A0 Architecture Discovery** → Score → Propose → Plan → Gate → Build via Agent Factory → Verify → Register Capability → Resume Observation

## Units
1. Systems Scout (Thinker)
2. Systems Architect (Planner)
3. Factory Orchestrator (Builder)
4. Challenger & Verification Agent (Reviewer)

## Authority
- Observe broadly across approved internal sources.
- Create internal discovery candidates and recommendations.
- Produce plans, system maps, run decompositions, and build specifications.
- No vendor action, spending, subscription/account changes, destructive actions, or external communication without separate explicit authorization.
- Builder routes approved work through existing Agent Factory; it does not create a parallel execution framework.

## Mandatory A0 rule
**No substantial new Factory Run may enter G0 until Run 007 records A0 = PASS.**

A0 must map the entire outcome/value chain, required capabilities, natural team/system boundaries, shared infrastructure, canonical data ownership, upstream/downstream contracts, dependencies, authority boundaries, operability, scale paths, and proposed Run sequence.

Trivial maintenance/bug fixes may be exempt only when the Challenger documents that the approved architecture is unchanged.

Canonical standard:
- `agent-factory/run-007/architecture/a0-architecture-discovery-standard.md`
- `agent-factory/run-007/architecture/system-map-template.md`

## Initial assignment
Evaluate the proposed personal/business operations modules, discover additional missing capabilities, identify shared infrastructure, detect duplication, and recommend the optimal build sequence.

## Initial candidate modules
- Inbox & Obligation Manager
- Bills / Payments / Renewal Manager
- Waiting-On / Follow-Up Manager
- Document & Expiration Manager
- Project / Workload Control Manager
- Account & Security Watch
- Purchase / Warranty Manager

## Success condition
Run 007 is successful when it produces and maintains a prioritized, evidence-backed capability roadmap that distinguishes:
- shared infrastructure to build once,
- modules/teams to build next,
- modules to defer,
- existing capabilities to reuse,
- risks or blind spots the owner has not yet identified,
- and, before each substantial Run, an approved A0 System Map Package that makes the Run's upstream/downstream boundaries explicit.

## Architecture amendment rule
If later evidence reveals a materially missing team, store, handoff, dependency, or authority boundary, Run 007 issues an Architecture Amendment and determines whether the current Run should be patched, a new upstream/downstream Run should be created, shared infrastructure should change, or further authority should pause.
