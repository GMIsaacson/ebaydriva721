# Run 009 — G4 Repeatable Shadow Automation

## Objective
Convert the supervised G3 workflow into deterministic, repeatable internal machinery without granting customer delivery, outreach, spend, or unattended production authority.

## Implemented
- canonical candidate normalization
- pilot-geography fail-closed check
- deterministic project deduplication
- duplicate evidence merging
- confidence-floor enforcement
- missing electrical-thesis rejection
- rejection-reason repair for traceability
- ranked internal opportunity feed
- zero-external-action invariant
- automated regression tests against the 25-project G3 shadow fixture

## G4 acceptance criteria
1. Reproduce the G3 25-candidate result: 17 ACTIONABLE, 3 WATCH, 5 REJECTED.
2. Duplicate project inputs collapse to one canonical record and preserve source evidence.
3. ACTIONABLE records below 0.75 confidence are demoted rather than confidence-inflated.
4. ACTIONABLE records without a defensible electrical thesis are rejected.
5. Outside-pilot geography fails closed.
6. Customer-facing/external action count remains zero.
7. Ranked feed excludes rejected records.
8. GitHub CI passes the G3 and G4 regression suites.

## Current boundary
This is repeatable analysis/QA machinery, not autonomous live collection. Municipal source fetching/parsing connectors and recurring schedules remain unauthorized. G5 should validate source connectors in controlled read-only mode before any customer delivery or monetization activity.
